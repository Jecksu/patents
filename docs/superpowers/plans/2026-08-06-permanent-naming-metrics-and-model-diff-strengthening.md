# 永久命名质量门控与关系闭包强化实现计划

> **面向 AI 代理的工作者：** 必需子技能：使用 superpowers:subagent-driven-development（推荐）或 superpowers:executing-plans 逐任务实现此计划。步骤使用复选框（`- [ ]`）语法来跟踪进度。

**目标：** 将永久命名强化设计改造成经新增现有技术校验、数学定义闭合、权利要求分层清楚且具有可复算技术效果的授权稳健方案。

**架构：** 以比较开始前已经存在的永久命名索引为输入，用实体—比较规范键关联关系保留映射基数；将身份判定与变化判定分开，并通过可信／歧义／冲突／低信息状态控制验证路径。对一对一、一对多和多对一关系假设执行双侧端点互斥选择，冻结未决端点，以双侧分区不变量主动触发回滚或局部扩读，闭包成立后才输出类型化差异事件。

**技术栈：** 中文 Markdown、集合与关系代数、CAD B-rep／特征／装配实体模型、PowerShell 文本核查。

### 任务 2：闭合数据模型和命名质量指标

**文件：**
- 修改：目标稿第4至8节

- [x] **步骤 1：将“规范命名键”明确为比较规范键**

定义比较规范键只由已有名称标准化得到，只用于本次比较且不回写 CAD／PDM 永久命名索引。

- [x] **步骤 2：定义实体—键关联关系及映射基数**

使用 `P_X⊆U_X^l×K_X` 表示关联关系，并由其导出 `E_X(k)` 与 `K_X(e)`；明确它不是把原始名称去重后的普通键集合。

- [x] **步骤 3：补齐映射覆盖率**

定义需要跨域映射的源实体集合 `U_src`、至少具有一个有效目标映射的实体集合 `U_mapped`，给出 `C_mapcov` 的实体加权公式和空分母规则；保留 `C_mapconf` 为冲突记录或受影响端点口径并明确二者不同。

- [x] **步骤 4：修正一致性评分域**

定义 `K_score` 为无硬冲突且至少有一个可用身份分量的共有唯一键，`K_lowinfo` 为无可评分分量的键；`S_cons` 只在 `K_score` 上求均值，`R_cons` 的分母仍为全部 `K_11`，硬冲突和低信息均不算通过，并分别报告硬冲突率和低信息率。

- [x] **步骤 5：定义全局与局部门控状态机**

区分三种状态：元数据硬门控失败时禁用全部名称直配；元数据通过但全局质量未通过时允许逐键临时可信关系；全局质量通过时仍只允许逐键审计通过者进入快速路径。

### 任务 3：重构候选关系、组关系和联合选择

**文件：**
- 修改：目标稿第9节

- [x] **步骤 1：拆分临时可信关系和最终关系**

用 `R_seed` 表示经名称审计得到但仍需身份或指纹验证的临时可信关系，用 `R_11` 表示验证后的最终一对一关系，避免 `R_name` 同时表示临时和最终状态。

- [x] **步骤 2：把异常候选定义为稀疏关系**

把候选关系改为 `C⊂U_A^abn×U_B^abn`，说明先通过类型、层级、空间索引、语义约束或可选的已验证关系上下文生成候选边，再在边上计算评分；不得用公式表示先枚举全部异常实体笛卡尔积。

- [x] **步骤 3：定义关系假设集合**

分别定义一对一假设 `H_11`、一对多假设 `H_1m⊆U_A×P_≥2(U_B)` 和多对一假设 `H_m1⊆P_≥2(U_A)×U_B`，并按实体层级给出适用的验证条件。

- [x] **步骤 4：联合选择最终关系**

在同一局部候选分量中联合选择 `R_11`、`R_1m`、`R_m1`，要求模型A和模型B的最终端点集合分别两两不交；不得先用普通一对一最大权匹配占用可能属于分裂／合并的端点。

- [x] **步骤 5：冻结未决端点**

候选并列、验证数据不足、局部读取失败或验证预算超限时，把相关端点放入 `FROZEN_A`、`FROZEN_B`，并记录冻结原因和下一验证动作。

### 任务 4：把关系闭包改为主动校验和回滚机制

**文件：**
- 修改：目标稿第10至11节

- [x] **步骤 1：正式定义组关系端点算子**

定义 `end_A(R)`、`end_B(R)` 对一对一和组关系均返回全部端点并集，避免对不同类型关系直接使用未定义的普通 `dom/ran` 并集。

- [x] **步骤 2：重写双侧分区不变量**

模型A端点必须由 `end_A(R_11)`、`end_A(R_1m)`、`end_A(R_m1)`、`DEL`、`FROZEN_A` 不相交并集构成；模型B使用相应关系端点、`ADD`、`FROZEN_B`。

- [x] **步骤 3：增加失败后的机器动作**

分区出现重复端点、遗漏端点或与冻结集合冲突时，按低置信度撤销关系、扩大失败局部的 CAD 数据读取范围、重新生成组关系假设，或把端点转入冻结集合；不变量通过前禁止输出确定性增删。

- [x] **步骤 4：统一差异事件类型**

定义 `event=(type,A_endpoints,B_endpoints,primary_class,secondary_labels,evidence)`；`DIFF` 只包含同一事件记录类型，不能再直接混合实体、实体对、组关系和待复核集合。
